# KTS ALL-SURFACE FIX CONTRACT — CODEX AGENT INSTRUCTIONS

Applies to every KTS bug fix, parser change, station/region change, money rule, customer flow, or UI behavior change. This is an **acceptance gate**; a one-surface fix is never "DONE".

## Authority and boundaries
- Repositories: `wilson86/KTS` (Router/Bridge, shared business engine, DesktopRecovery), `wilson86/tach-dai-mobile` (standalone Tách Đài and embedded Unified/Đá Vòng), and `wilson86/tach-dai-ngang` (standalone Tách Ngang). Treat backend, reports, generated adapters, deployment/cache metadata and Android PWA as separate consumers.
- Resolve the **actual code-bearing KTS release branch** and full SHA before changing anything. Do not assume KTS `main` contains Router; it is a separate Message Bridge line. Inspect ancestry of each of the three repositories and record exact base/HEAD SHAs.
- SharedBusinessEngine `engine_spec.json`, calendar authority and generator are the source for common money/station rules. Do not independently alter generated artifacts, silently overwrite a release, or downgrade app/cache versions. Different allocation semantics between Tách Đài and Tách Ngang remain intentional.
- Preserve raw Telegram/source text byte-for-byte and raw source physical line numbers. Source-derived normalizations must be explained, deterministic and auditable. No inference from blank lines, previous customers or unrelated message blocks.
- User sends are never authorized merely by a passing test. Never send/ACK/return a real customer message, reset/reconcile live checkpoints, modify production SQLite, trigger live automation, merge, publish or deploy without an explicit separate user approval.

## EVERY FIX — required cross-surface matrix
1. Reproduce with the original source and redacted offline fixture; identify the exact failing entry point.
2. Enumerate direct Router/engine bridge, runtime backend, Desktop Python, Mobile standalone `run()/validateBatch`, Ngang standalone, Unified iframe and Đá Vòng, PWA service workers/cache, and client/report paths. Mark each `CHANGED`, `UNMODIFIED_BY_DESIGN` with evidence, `PASS`, or `BLOCKED`. Never infer UI acceptance from Router bridge PASS.
3. Define **allowed** inputs and **rejected/HOLD** inputs. For unrecognized or ambiguous source, **fail closed**: clear all materialized sibling outputs, report correct original line, do not dispatch, send, ACK, increment customer sequence or produce a money/settlement result. No silently dropped wager-containing line, unknown operator, unknown station, amount, or mixed markup.
4. An entire standalone divider composed of >=3 approved `-`, en/em dash, `_`, `/`, backslash or `|` is non-betting metadata; mixed text is NOT a divider. All-divider input is `EMPTY_AFTER_PREPROCESS`/HOLD (never PASS). Preserve correct physical mapping after blank lines/chat envelopes and CUT/Undo.
5. Before changing parser behavior, inspect the **approved** negative/positive corpus at `wilson86/KTS:KTSRouter/tests/ingress_adversarial_cases.json`. Classify each new real-world format as `APPROVED`, `NEEDS_ORACLE` or `REJECTED_AS_INVALID_FIXTURE`. Do not enforce unapproved guesses. Add regression for every confirmed bug and its nearest valid lookalike.
6. Test all affected surfaces against the same immutable source/corpus ID: correct acceptance/rejection, region and date-specific station schedule, exact split, money conservation, customer checkpoint, duplicate suppression, source line provenance, no-send/shadow, and cross-app contract parity. Preserve known legitimate valid formats including compact Telegram punctuation, B+DA, DX, ĐẦU/ĐUÔI, full station names, aliases, MB cuts and customer Quýt multiplier.
7. Check generated engine SHA and portable manifest, version.json, APP_VERSION, service-worker cache key/fallback, Unified iframe URLs, and current Mobile/Ngang features. Android manual smoke testing is mandatory **after separately approved deployment**; a GitHub push cannot prove the phone is updated.
8. Show exact SHA-specific receipts: `INPUT_CASES, APPROVED_NEGATIVE_PASS, APPROVED_POSITIVE_PASS, UNREVIEWED_CASES, MONEY_STATUS, SOURCE_LINE_PROVENANCE, ROUTER_PARITY, DESKTOP_PARITY, MOBILE_PARITY, NGANG_PARITY, UNIFIED_DAVONG_PARITY, BACKEND_PARITY, GENERATED_PARITY, CACHE_STATUS, CHECKPOINT_STATUS, TESTS_PASS/FAIL/SKIP, COST_USD, PRODUCTION_MUTATION, RELEASE_READINESS, NEXT_SAFE_ACTION`.
9. If any mandatory surface has no code access or evidence, mark `BLOCKED`, not `PASS`. Do not promote past `READY_FOR_HUMAN_RELEASE_REVIEW` without human release approval, rollback readiness and on-device acceptance.

## Autonomous bounded goal loop
- Work in isolated checkout/worktree (prefer C: on Windows). Read AGENTS and scope, start from exact verified SHA. Never read/write the user's F:; E: production is READ-ONLY unless explicitly authorized, and no production SQLite/session access.
- Execute **up to 3 related tasks per batch**, then persist a durable SHA-bound checkpoint, failing tests and next safe tasks. Continue the next batch **within the same interactive Codex session without waiting for a fresh user message**, until no safe task remains, a real blocker occurs, quota/user stop, or safety/cost boundary would be crossed. Never auto-launch an unbounded background agent/executor.
- `COST_USD=0`. No paid CI, no paid model/API services, no Telegram transport. Prefer local Node/Python deterministic tests; reuse prior PASS only when source, test and relevant environment identity match; do not claim a skipped gate passed for modified source.
- Feature branches and commits/pushes are allowed only after local evidence, and only in isolated candidates. Never merge to main, release, publish PWA, deploy Router/Desktop or update live caches automatically.
- A defect found on *any* surface reopens the whole matrix, not just that surface. End with an explicit release gate and checkpoint suitable for a new ChatGPT conversation.
